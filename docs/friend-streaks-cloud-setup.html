Gym Tracker Friend Streaks Cloud Setup Guide

This guide covers the setup needed for online friend streak sharing and encouragement reactions in Gym Tracker.

Backlog issue #19Cloudflare WorkerD1 databaseOptional Firebase Cloud Messaging

Recommended Architecture

Keep the app local-first. Sync only lightweight social data to the cloud, not full workout history.

Cloudflare Worker API

Public HTTPS API used by the Android app for friend identity, friend links, streak summaries, and reactions.

Cloudflare D1

Small relational database for users, devices, friendships, streak summaries, reactions, and optional push tokens.

Firebase Cloud Messaging

Optional push notification channel. Use this only when reactions should appear as Android notifications outside the app.

Privacy rule: The cloud service should store summary data only: display name, current week workout count, weekly streak, last workout date, reaction messages, and device notification token if push is enabled.

Phase 1: Cloudflare Setup

  1. Confirm Wrangler is installed and authenticated on the development PC.
  2. Create a new Worker project in the repo, for example cloudflare/gym-tracker-social-api.
  3. Create a D1 database, for example gym-tracker-social.
  4. Bind the D1 database to the Worker as SOCIAL_DB.
  5. Create a local migration file for the tables listed in this guide.
  6. Run the migration locally for testing.
  7. Run the migration remotely when the API is ready for a real test.
  8. Deploy the Worker to a workers.dev URL first.
  9. After testing, optionally add a custom route/domain.

Suggested Worker Commands

npm create cloudflare@latest -- gym-tracker-social-api
cd gym-tracker-social-api
npx wrangler d1 create gym-tracker-social
npx wrangler d1 migrations create gym-tracker-social initial_social_schema
npx wrangler d1 migrations apply gym-tracker-social --local
npx wrangler d1 migrations apply gym-tracker-social --remote
npx wrangler deploy

Suggested D1 Tables

users (
  id TEXT PRIMARY KEY,
  display_name TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

devices (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  device_public_id TEXT NOT NULL,
  device_secret_hash TEXT NOT NULL,
  fcm_token TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

friendships (
  id TEXT PRIMARY KEY,
  user_a_id TEXT NOT NULL,
  user_b_id TEXT NOT NULL,
  status TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

streak_summaries (
  user_id TEXT PRIMARY KEY,
  week_id TEXT NOT NULL,
  workouts_this_week INTEGER NOT NULL,
  consecutive_weeks INTEGER NOT NULL,
  last_workout_date TEXT,
  updated_at TEXT NOT NULL
);

reactions (
  id TEXT PRIMARY KEY,
  from_user_id TEXT NOT NULL,
  to_user_id TEXT NOT NULL,
  type TEXT NOT NULL,
  message TEXT,
  workout_date TEXT,
  created_at TEXT NOT NULL,
  read_at TEXT

Phase 2: API Design

EndpointMethodPurpose
/v1/registerPOSTCreate or recover the user's cloud identity and device record.
/v1/friend-codeGETReturn a QR/invite payload for adding a friend.
/v1/friends/acceptPOSTCreate a friendship after QR or invite-code exchange.
/v1/streakPOSTPublish the signed-in user's streak summary after workouts change.
/v1/friendsGETReturn friends and their visible streak summaries.
/v1/reactionsPOSTSend thumbs up, fire, or another allowed reaction to a friend.
/v1/inboxGETFetch unread reactions for the current user.
/v1/inbox/readPOSTMark reactions as read.
/v1/push-tokenPOSTSave or rotate the device FCM token when push is enabled.

Do not put a master API secret inside the APK. Each install should generate a device secret, register it once, and sign future requests or present a scoped token issued by the Worker.

Phase 3: Android App Changes

  1. Add a Friend Sync opt-in toggle in the Friends or User section.
  2. Generate a cloud user ID and device ID after opt-in.
  3. Add QR/invite-code exchange for online friendship linking.
  4. After a workout is completed, compute and upload the user's streak summary.
  5. Change the Friends roster to show workouts this week, weekly streak, and last workout date.
  6. Add thumbs up and fire reaction buttons for online friends.
  7. Add an in-app reaction inbox or notification area.
  8. Cache the last fetched friend summaries locally so the Friends tab still works offline.
  9. Show clear offline or sync-failed status without blocking workout logging.

Phase 4: Firebase Setup For Push Notifications

This phase is optional. The first version can work by showing reactions inside Gym Tracker whenever the app opens or syncs.

  1. Create or open a Firebase project in the Firebase console.
  2. Add an Android app to the Firebase project using package name com.homeops.gymtracker.
  3. Download google-services.json.
  4. Place google-services.json in the Android app module root: app/google-services.json.
  5. Add the Google Services Gradle plugin and Firebase Messaging dependency to the Android project.
  6. Add a Firebase messaging service class to capture FCM registration tokens.
  7. When FCM creates or refreshes a token, send it to the Cloudflare Worker at /v1/push-token.
  8. Create a Firebase service account credential for server-side sending.
  9. Store the service account JSON in Cloudflare as a Worker secret. Do not commit it to GitHub and do not embed it in the APK.
  10. Update the Worker so sending a reaction can optionally call the FCM HTTP v1 API for the recipient's device token.
  11. Test push from Firebase console first, then test app-to-app reaction push through the Worker.

Owner Setup Checklist

  1. Confirm the Cloudflare account and workers.dev subdomain are available.
  2. Approve a Worker name, recommended: gym-tracker-social-api.
  3. Approve a D1 database name, recommended: gym-tracker-social.
  4. Decide whether version 1 should be in-app only or include Android push notifications.
  5. If push notifications are wanted, create the Firebase project and Android app.
  6. If push notifications are wanted, provide google-services.json for placement in the app.
  7. If push notifications are wanted, provide the Firebase service account JSON through secure input so it can be added as a Cloudflare secret.
  8. Approve privacy wording for friend streak sharing opt-in.
  9. Test with two phones or two app profiles before publishing.

Suggested MVP Scope

Build this in two releases:

  1. Release A: Cloudflare Worker, D1, friend streak sync, and in-app reactions/inbox. No Firebase push yet.
  2. Release B: Add Firebase Cloud Messaging for push notifications after the social API is stable.

This reduces risk because the app remains useful even when the phone is offline, and push notification setup does not block the core feature.

Test Plan

  1. Install the test APK on two devices or two test users.
  2. Opt in to friend streak sharing on both.
  3. Exchange friend codes.
  4. Complete a workout on device A.
  5. Open Friends on device B and verify workouts this week and weekly streak update.
  6. Send thumbs up from device B to device A.
  7. Verify device A sees the reaction in-app.
  8. If Firebase is enabled, verify device A receives a push notification while the app is backgrounded.
  9. Disable network and verify normal workout logging still works.
  10. Reconnect and verify queued streak/reaction sync completes.
